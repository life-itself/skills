# Session handoff: the focus-label pattern

How to close one agent session and start the next one cleanly, without handoff files. Worked out on the Seeds of Renaissance website, 2026-10-16.

## Principle

Durable state lives where it already belongs: docs, beads, memories. The handoff itself is only a pointer. A separate handoff file or a long pasted block duplicates the truth and goes stale within a day.

## The pattern

1. **One static rule in `AGENTS.md`**, added once and never edited for handoffs:
   > At session start, run `bd list --label=focus` and read each focus bead's notes: that is the current work and its status. Move the `focus` label (and update the notes) when the focus changes; do not edit this file for it.
2. **A `focus` label on the current bead or beads** (usually an epic). Change focus by moving the label:
   ```
   bd update <old> --remove-label=focus
   bd update <new> --add-label=focus
   ```
3. **Live status in the focus bead's notes** (`bd update <id> --notes=...`), in this order:
   - **Read first:** the two or three docs that matter.
   - **In flight:** which side sessions own what, so the next session messages them rather than redoing their work.
   - **Next:** the order of work.
   - **Open for the human:** decisions and inputs only they can give.
4. **Working rules as beads memories** (`bd remember "..."`): how the human wants work done, e.g. "every open question carries a recommendation". `bd prime` surfaces them to every new session and every agent, not just one tool's memory.
5. **Kickoff:** a new session needs no handoff prompt, because `AGENTS.md` sends it to the focus beads. If one is wanted: "Read AGENTS.md, run `bd list --label=focus`, and act as coordinator."

## When beads are not enough

Rarely, a bead cannot hold what the next session needs. Prefer, in order:
1. **The work plan itself.** The bead's notes point into a plan or design doc that already exists for the work; no extra handoff file.
2. **A beads memory** (`bd remember`) for a rule or fact that outlives the task.
3. **A special handoff document**, only in a specific case: reference it from the focus bead's notes, and delete it once the next session has absorbed it. Nothing handoff-shaped stays in the git repo.

## Before closing a session

- Pull and push both code and beads (`git pull --rebase`, `git push`; check the Dolt sync).
- Move anything durable out of the conversation: decisions to the project record, settled content to docs, work-in-progress research to a short note in `docs/plans/`.
- Delete or merge superseded docs rather than marking them "superseded"; git history keeps them.
- Update the focus bead's notes. Then the conversation can be thrown away.

## Why not `bd ready`?

`bd ready` lists every unblocked task, often dozens. It does not say which one matters now. `focus` is the "start here"; `bd ready` stays the full list of work available.

## Anti-patterns

- Editing `AGENTS.md` with "current work" each time: it should stay static.
- A `HANDOFF.md` or `NEXT.md` that repeats the task queue.
- Status that exists only in the chat transcript.
