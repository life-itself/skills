# Reply shape

How these skills write anything a person has to read: chat replies, play-backs, sweep reports, briefings and docs. The reader should see in a few seconds what they need to do and can skip the rest. Examples: [reply-examples.md](reply-examples.md).

1. **TL;DR first.** One or two plain sentences: the answer or the state of things.
2. **You:** only what needs the reader, at most 3 items. Each one is a decision or an action, marked *big* (hard to reverse, or theirs to judge) or *small*, with a recommendation and one line of reasoning. If nothing needs them, leave this out.
3. **Decided:** small, reversible choices you made yourself, one line each. Do not ask about these.
4. **Detail last, or linked.** Tables, evidence and method go below the asks, in an appendix or in a file you link. Never put them above the asks.
5. **Plain names.** Name a thing before giving its ID ("Fable examples (pl-m2u8)"). No unexplained internal labels.
6. **Write for the named reader.** Leave out what they already know or designed; a briefing should be a 5–10 minute read at most.

Default length for a chat reply is about 150 words. Go longer only when the reader asked for depth, and even then keep 1–3 on top.
