# Reply shape

How these skills write anything a person has to read: chat replies, play-backs, sweep reports, briefings and docs. The reader should see in a few seconds what they need to do and can skip the rest.

A chat reply puts any detail first, then ends with one closing block, so the reader's eye lands on it after scrolling. If there is detail above, start the block with a `---` line to separate it.

1. **`### Summary`.** One short sentence with the answer or the state of things. Add up to 4 short bullets, one fact each, only if needed; often the sentence is enough. Not a paragraph. Example:
   > ---
   > ### Summary
   > Course gets its own section on the knowledge-base site.
   > - Chapter sidebar for navigation.
   > - JavaScript does work on Flowershow (I was wrong earlier), so polls and small games are possible.
   > - Chapters 0 and 1 drafted, ready for you to read. Nothing published.
2. **`### You`.** Everything that needs the reader, at most 3 items: decisions, actions, or things worth reviewing. For a choice, give a clear recommended option with one line of reasoning, plus backup option(s) if needed. If nothing needs them, leave the heading out.
3. **No Decided section.** Note small, reversible choices you made in the detail above, one line each. If one is worth the reader checking, it goes under **You**.
4. **Detail sits above the block, or is linked, and doesn't repeat it.** Tables, evidence and method go in the detail, an appendix or a linked file. Anything the Summary says is cut from the detail. Nothing goes after **You**.
5. **Plain names.** Name a thing before giving its ID ("Fable examples (pl-m2u8)"). No unexplained internal labels.
6. **Write for the named reader.** Leave out what they already know or designed; a briefing should be a 5–10 minute read at most.

**Documents** are read top-down, so there the Summary and **You** block go at the top instead.

Go longer than about 150 words only when the reader asked for depth.
